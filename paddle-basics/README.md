# Paddle Basics

Основа игры на JavaFX: серое поле 720 x 1280 (9:16) и управляемая пластина.

## Запуск

Нужны JDK 21 или новее и Maven. JavaFX загружается через pom.xml.

В IntelliJ IDEA: откройте папку проекта как Maven-проект, выберите Project SDK
и запустите класс com.platon.paddle.Launcher.
Или выполните из папки с pom.xml:

```shell
mvn javafx:run
```

## Управление и настройки

- Только WASD: A — влево, D — вправо, W — вверх, S — вниз. Клавишу можно удерживать. Стрелки отключены.
- Движение по диагонали имеет ту же скорость, что и движение по одной оси.
- После переключения в другое окно движение сбрасывается.
- Размер игровой области: 720 x 1280. Окно имеет фиксированный размер.
- Пластина: 140 x 18; скорость: 500 пикселей в секунду.
- Координаты отсчитываются от верхнего левого угла; Y растёт вниз.
- Левый верхний угол пластины ограничен X: 40..540, Y: 832..1222.
  Поэтому пластина остаётся в нижних 35% поля и имеет отступы от краёв.
- Все эти значения находятся в GameConfig.java. Например, уменьшите MIN_Y,
  чтобы пластина могла подниматься выше.

## Текущие классы

| Класс | Ответственность |
| --- | --- |
| Launcher | Точка запуска из IDE или Maven |
| GameApp | Создание окна, клавиатура, игровой цикл |
| GameConfig | Размеры, скорость и границы движения |
| Paddle | Положение, фактическая скорость и ограничение движения |
| GameView | Отрисовка фона и пластины на Canvas |

AnimationTimer вызывает обработку каждого кадра. Накопленное время обрабатывается
шагами по 1/120 секунды; затем рисуется кадр. Скорость задаётся в пикселях в секунду,
а не в пикселях за кадр. После долгой паузы обрабатывается не более 0.1 секунды,
чтобы игра не делала большой скачок.

## Как развивать приложение дальше

Добавляйте классы по мере реализации, в таком порядке:

1. Ball: положение x/y, скорость vx/vy, радиус, масса и материал.
   Эти данные должны оставаться независимыми от JavaFX.
2. GameWorld: коллекции мячей и боковых блоков, пластина; обновление всех объектов.
3. PhysicsEngine: силы, движение, столкновения и отскоки.
   GameApp будет вызывать world.update(dt), а GameView — читать состояние мира.
4. TargetBlock: прямоугольные границы блока и его идентификатор/цвет.
5. RoundManager: выбор нужного блока, попадание/промах, очки и создание следующего мяча.
6. GameView: отрисовка мячей, блоков и задания сверху.
   Если управление разрастётся, вынесите pressedKeys и axis() в InputController.

Не помещайте обработку столкновений в GameView. Физика меняет данные мира,
отрисовка только показывает их. Для начала достаточно одного класса Ball
и настроек Material/BallType; отдельный подкласс для каждого веса не требуется.

## Разные веса и физика

Масса сама по себе не делает падение в вакууме быстрее: под гравитацией все мячи
имеют одинаковое ускорение g. Различайте массу, размер, сопротивление воздуха
и упругость материала.

Простейшая модель: линейное сопротивление воздуха F_drag = -k * v.

```text
ax = -k * vx / mass
ay = gravity - k * vy / mass
vx += ax * dt
vy += ay * dt
x  += vx * dt
y  += vy * dt
```

Это полунеявный метод Эйлера. При одинаковом k лёгкий мяч сильнее реагирует
на сопротивление, но коэффициент также зависит от формы/размера и выбранной модели.
Для больших скоростей можно перейти к сопротивлению, пропорциональному квадрату
скорости. Материал удобно описывать записью:

```java
record BallMaterial(double mass, double radius,
                    double restitution, double dragCoefficient) {}
```

mass должна быть > 0, restitution обычно выбирают от 0 до 1. Смешивая метры
и пиксели, сначала задайте масштаб; для первого прототипа все координаты и скорости
можно считать в пикселях и пикселях/сек, а gravity — в пикселях/сек².

Для удара о движущуюся пластину используйте относительную скорость
vRelative = vBall - vPaddle. Если dot(vRelative, normal) < 0, отразите компоненту
по нормали с учётом упругости:

```text
vRelativeAfter = vRelative - (1 + restitution) * dot(vRelative, normal) * normal
vBallAfter = vRelativeAfter + vPaddle
```

normal — единичная нормаль от поверхности к мячу. Это модель управляемой пластины
с бесконечной эффективной массой: её движение задаёт игрок. При такой модели масса
мяча сама по себе не меняет отскок, поэтому разные материалы задают разную упругость
и сопротивление. Если нужна отдача пластины от тяжёлого мяча, ей тоже нужна конечная
масса и расчёт импульса с обратными массами обоих тел.

При круге против прямоугольника находите ближайшую к центру мяча точку
прямоугольника. Если расстояние меньше радиуса — контакт; сначала исправьте
проникновение, затем меняйте скорость только при сближении. Для центра внутри
прямоугольника выбирайте ближайшую грань: нулевой вектор нельзя нормализовать.
Быстрые мячи могут проскакивать даже при шаге 1/120: далее понадобятся подшаги
или непрерывная проверка столкновений (swept collision).
